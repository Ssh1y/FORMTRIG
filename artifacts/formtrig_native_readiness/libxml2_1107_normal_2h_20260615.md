## Why `_T` Did Not Appear

Direct replay shows that terminal crashing inputs were generated during the
normal 2-hour run:

```text
02 61 exit=139
02 00 exit=139
02 7c exit=139
```

Those inputs were saved under AFL++ `hangs/`, not `crashes/`:

```text
saved_crashes=0
saved_hangs=3
```

The AFL++ run log explains the classification risk:

```text
No -t option specified, so I'll use an exec timeout of 20 ms.
core dump notifications ... will cause issues ... crashes misinterpreted as timeouts
```

The runtime `_T` counter remained zero for a separate reason. The current
BindingSpec observes the root null check at `xmlregexp.c:741`:

```c
ret->len = strlen((const char *) ret->string);  // line 740
if (ret->string == NULL) {                      // line 741
```

For the terminal input, `ret->string` is NULL and the program crashes at the
`strlen` use on line 740. The post-use null check on line 741 is therefore not
executed, and the process dies before the runtime can publish a
`FORMTRIG_FLAG_CRASH_PREDICATE` record. That is why:

```text
formtrig_triggered_execs=0
triggered_events=0
saved_triggered_progress_events=0
```

## Interpretation

The normal 2-hour run is positive evidence for FORMTRIG's R2T guidance, but it
is not positive evidence for runtime `_T` accounting:

- Positive: FORMTRIG produced spec-driven, non-trigger, replay-stable progress
  while binary `D_T` stayed uninformative.
- Positive: typed mutation generated terminal crashing inputs (`02 xx`) in the
  run.
- Negative/accounting gap: those terminal inputs were counted as AFL hangs due
  timeout/core-pattern behavior and were not counted as FORMTRIG `_T` because
  the crash happens before the current post-use root-observe site.

The immediate fix is not to claim `formtrig_triggered_execs` for this run. The
next engineering step is to make the terminal predicate observable before the
unsafe use, or to run terminal-accounting with a timeout/core-dump setup that
classifies these inputs as crashes. For FORMTRIG-native `_T`, the BindingSpec
should bind a pre-use nullness observation or an explicit crash predicate before
`strlen(ret->string)`, rather than relying on the unreachable post-crash null
check.
